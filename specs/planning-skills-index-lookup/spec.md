# Spec: planning-skills-index-lookup

> Feature issue: [your-org/kadence#26](https://github.com/your-org/kadence/issues/26)
> Part of epic: [prashanthm/product-workspace#666](https://github.com/prashanthm/product-workspace/issues/666) (`planning-index-and-context-discovery`)

## Behavior

Add a required "read `INDEX.md` first" step to three existing planning-layer skills —
`skills/feature-generation/SKILL.md`, `skills/epic-generation/SKILL.md`, `skills/spec-author/SKILL.md` —
so that each, before drafting new epic/feature/spec content, reads the relevant initiative's `INDEX.md`
(generated by `scripts/generate_initiative_index.py`, see `specs/initiative-index-generator/spec.md`) as a
duplication check.

This is a prompt-doc feature: the "implementation" is the SKILL.md instruction text itself, since these
files are the executable artifact an agent follows. There is no application code or script to write. Each
edit is treated with the same scope discipline as a code change — touch only the required sections of the
three named files, no unrelated skill-doc rewrites.

### Required step, present in all three skills

Each skill's `## Required Workflow` gains an explicit numbered step (inserted before the step that begins
drafting new content) that:

1. **Locates and reads `INDEX.md`** for the initiative in scope, at `initiatives/<slug>/INDEX.md` (relative
   to product-workspace — the initiative-owning repo, not necessarily the code repo the skill itself is
   invoked from for dedicated-code-repo initiatives). The initiative slug is derived the same way each
   skill already derives it for GitHub Issue Sync (from the epic/feature/spec's path or `Part of epic:`
   link).
2. **Degrades gracefully when `INDEX.md` doesn't exist** (the bootstrap case — a brand-new initiative with
   no generated index yet, or an initiative predating this feature): the skill proceeds with its normal
   workflow, but notes the caveat ("`INDEX.md` not found — proceeding without an index-based duplication
   check") rather than blocking or failing. This is explicit in each skill doc, not left to inference.
3. **Surfaces apparent overlap before drafting**: scans the index's flat Features table (`| Slug | Parent
   Epic | Scope | Doc |`, per `specs/initiative-index-generator/spec.md`) — and, for `epic-generation`, the
   Epics table; for `spec-author`, any Features table row other than the feature being specced — for a row
   whose `Scope` text appears to describe the same capability as the work about to
   be drafted. If such a row is found, the skill **stops and presents that match** (slug, parent
   epic/scope, doc path) to the user/agent for confirmation **before** drafting new content — it does not
   silently proceed past an apparent match. This applies regardless of which epic the matching row sits
   under (the whole point is cross-epic discovery within the initiative — see the epic Problem statement: the
   original incident's collision was between sibling epics `saa-memory` and `saa-runtime` in the same
   initiative).

### Per-skill insertion points

- **`feature-generation`**: `## Required Inputs` currently lists "Existing features under the same epic" —
  this line is the root cause named in the epic Problem statement (scoped the search to "same epic" only,
  missing sibling-epic matches like `e03-f05-layered-memory` under `saa-runtime` while working `saa-memory`).
  Replace it with an INDEX.md-first instruction that is initiative-wide, not epic-scoped. `## Required
  Workflow` step 1 ("Size first...") gains the INDEX.md read + overlap-surfacing as an explicit prerequisite
  sub-step, since sizing/drafting begins immediately at step 1.
- **`epic-generation`**: `## Required Inputs` already says "Related prior epics/features in the same
  initiative" (correctly initiative-wide already) — update it to point at `INDEX.md` as the fast path for
  that existing (already-correct-scope) requirement, rather than replacing the requirement itself.
  `## Required Workflow` gains the INDEX.md read + overlap-surfacing as step 1a, before step 2 ("Define epic
  scope").
- **`spec-author`**: has no existing-content lookup step at all today. Add one as a new step 2a in
  `## Required Workflow`, after "Confirm Depends On" (step 2) and before "Author the trio" (step 3) — spec
  drafting begins at step 3, so the check must land before it.

## Acceptance Criteria

- [ ] AC-1: `feature-generation`'s `SKILL.md` states, as a required (non-optional) workflow step, that it
      reads the parent initiative's `INDEX.md` before drafting new feature content; the prior
      epic-scoped-only `Required Inputs` line is replaced, not left alongside the new instruction as a
      contradictory narrower alternative.
- [ ] AC-2: `epic-generation`'s `SKILL.md` states the same required step before drafting new epic content.
- [ ] AC-3: `spec-author`'s `SKILL.md` states the same required step before drafting new spec content.
- [ ] AC-4: Each skill's lookup step documents graceful degradation (proceeds with a noted caveat, does not
      fail/block) when `INDEX.md` does not exist yet for that initiative.
- [ ] AC-5: Each skill's lookup step documents the match-surfacing behavior: an apparent overlap in the
      index's flat table must be presented to the user/agent for confirmation before drafting — not
      silently passed over.
- [ ] AC-6 (regression, epic AC-7): re-running the original incident scenario — an agent working
      `saa-memory` (which today only has ADR-017/ADR-018 features) asked to plan/build a memory subsystem —
      following the newly-edited `feature-generation` `SKILL.md`'s required workflow (read `INDEX.md`
      first) surfaces `e03-f05-layered-memory` (filed under sibling epic `saa-runtime`) as a match before
      any new feature is proposed.

## Out of Scope

- The `INDEX.md` generator itself (`scripts/generate_initiative_index.py`) — already shipped by
  `initiative-index-generator` (this feature's `Depends On`).
- CI regeneration of `INDEX.md` — `index-ci-regeneration-workflow`, a sibling feature.
- `AGENTS.md` bootstrap/lifecycle wiring — `agents-md-bootstrap` / `agents-md-initiative-lifecycle`,
  sibling features.
- The code/test-layer live-search requirement for `implement` / `test-generation` —
  `code-skills-mandatory-live-search`, a sibling feature; deliberately a different mechanism (live grep,
  not an index) per the epic Notes.
- Any change to `scripts/generate_initiative_index.py`'s table format.

## ADRs Applied

None — this is a skill-workflow wiring capability (a required lookup step added to three existing skill
docs), not an architectural or system-boundary decision, matching the parent feature issue's ADR section.
